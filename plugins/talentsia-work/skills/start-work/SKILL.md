# Start Work

Read [the seat protocol](references/seat-protocol.md) before proceeding, then follow the seat's own procedures from `how_this_seat_works`; they override this skill on how the work is done.

Start every session the same way, and do no work before step 3.

1. `how_this_seat_works`: the seat's procedures and rules as they stand today. They override this skill on how the work is done. Keep them in mind for the session and write them nowhere.
2. `objectives`, then `my_tasks`. Work delegated to the seat shows as `ready`. Work the device's own worker could not finish shows as `waiting_for_user`. Work the seat already holds shows as `working`. Read the ones that matter with `read_task`, and use `read_deliverables` for anything they build on.
3. Show the person a short list: each item, what it asks for, what it serves and what finished looks like. Recommend one and say why. **Take a task with `take_task` only after they choose it.** Taking a task tells the organisation somebody is on it.
4. As soon as the work begins, call `say_what_you_are_doing` with what you are starting. Post again when you change approach, when you file something and before any long gap.
5. Work by the seat's procedures and the person's direction, in this harness and with its own tools. When the work is ready, use Deliver Work. If you are stuck on something only the device or another worker can do, use Hand Over.

When nothing is waiting, say so plainly. That is a good answer, not a reason to invent work. When an item is unclear, read the task and its deliverables before asking. When it is still unclear, ask the person rather than guessing at what was meant.

**PT:** “O que tem para mim hoje na Talentsia?” Read procedures, objectives and tasks, then recommend one item and take nothing yet. **EN:** “Pick up the carousel task.” Take it, post that you have started, then work.
